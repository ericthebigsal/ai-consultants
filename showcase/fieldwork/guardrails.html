Part 04

Fast, and still production-grade

The acceleration comes from doing the same process faster, not from skipping it. Every gate stays. Here's the full set of rules that keep AI-assisted work at the same bar as everything else Fieldwork ships.

6 human gates TDD enforced a short list of hard limits

The gates

Every point a person must sign off

These are the same gates Fieldwork had before Claude Code. None were removed.

  1. 1

    Requirements sign-off

    A named PM approves the requirements doc before design starts.
  2. 2

    Spec review

    Eng lead and PM both approve the functional spec.
  3. 3

    Architecture review

    Required for any schema change; a second reviewer for anything touching the response pipeline.
  4. 4

    Test-plan review

    QA approves coverage; the test plan is merged before any implementation PR.
  5. 5

    Code review

    Every PR reviewed and approved by an engineer. No PR merges on a machine approval.
  6. 6

    Release sign-off

    A person runs the deploy and watches the rollout.

The build rule

Test-first, enforced

  • The test plan is a merged artifact before any implementation PR opens. CI blocks an implementation PR whose feature has no merged test plan.
  • Every implementation PR adds or references the tests for what it changes. A PR that lowers coverage on a touched file needs an explicit reviewer waiver.
  • Claude Code works red-green-refactor: failing test, minimal implementation, refactor — the same loop a Fieldwork engineer uses.

The hard limits

What Claude Code can and can't do

Can

  • Draft any artifact — requirements, spec, architecture, tests, code, release notes
  • Open PRs and push to feature branches
  • Run tests, typecheck, and the local checks
  • Read the issue tracker, the staging schema, and the docs
  • Run migrations against a local or ephemeral database

Can't

  • Merge a PR — a human approval is always required
  • Change packages/auth, packages/billing, or packages/ingest without a senior making the change deliberately
  • Alter a migration already applied to staging or production
  • Deploy to production — ever
  • Modify the response-ingestion pipeline without a second reviewer and a load test
The escape hatch. If Claude Code is going in circles on a task — more than two iterations without progress — it stops and asks a person, rather than spending time (and tokens) on a guess.

Why this holds

Nothing here is specific to AI. It's the review discipline a well-run engineering team already has, written down and wired into CI so it applies the same way whether a person or Claude Code produced the change. The cycle comparison only counts the acceleration if the defect rate stays flat — and it stays flat because the gates stayed.
