CLAUDE.md

The repo's ground rules

Loaded into every session. Kept short so it's actually read.

# Fieldwork — CLAUDE.md (excerpt) Stack: TypeScript, React, Node, Postgres. pnpm workspace. Test: `pnpm test` (vitest). Property tests for logic: `pnpm test:logic`. Domain terms: respondent, complete (= validated submission), disposition, quota group, wave, screen-in / screen-out, piping. Never touch without a senior + explicit ask: - packages/auth/** # SSO, session, permissions - packages/billing/** - packages/ingest/** # the response-write hot path - any migration already applied to staging Always: test-first. One reviewable PR per slice. Surface design questions in the PR, don't defer them.

Subagents

Two review passes that run themselves

  • spec-reviewer — checks a drafted spec against the requirements: every requirement covered, out-of-scope stated, edge cases in the logic engine considered, ambiguities flagged rather than assumed.
  • schema-checker — checks a proposed schema or migration against the real staging schema (read-only): no name collisions, indexes where the queries need them, the change is reversible, nothing touches a protected package.
These don't replace human review. They catch the mechanical problems before a person looks, so the human review is about judgement, not spotting a missing index.

Hooks & commands

The rails

Hooks

  • On stop: run pnpm typecheck and pnpm lint; a failure is surfaced immediately, not at PR time.
  • Pre-commit: block any staged change under packages/auth, packages/billing, or packages/ingest — those need a human to make the change deliberately.

Slash commands

  • /new-feature — takes a ticket ID, runs the requirements → spec → test-plan flow, stops at each gate for review.
  • /ship — runs the release checklist: notes, migration order, rollback, load-test plan for any pipeline touch.
  • /quota-scenario — generates a test scenario for the quota engine (segments, targets, a sequence of completes) to reproduce a reported edge case.
