Analysis 04

Instructions nobody reads, sent 8 million times a month

The content assistant's system prompt has grown to 4,240 tokens — and it's re-sent uncached on every call. Half of it is stale examples and rules the platform now enforces itself. Trim it, cache it, and the input cost per call drops by about 78%.

4,240 → 680 tokens −84% prompt size win rate unchanged

Then cache it

The trimmed 680-token prompt is identical on every call — a textbook case for prompt caching. Combined with the trim, the input side of each request gets much cheaper.

# per content-assistant call, input tokens before: 4,240 system + 220 user = 4,460 tok, uncached, full price every call after: 680 system + 220 user = 900 tok, system portion cached after first call # effective input cost per call before ~$0.0067 after ~$0.0015 (-78%)

What stays

  • Prompts are reviewed like code — a change goes through the eval suite before it ships, and a diff shows what moved.
  • Guardrails live in one place (server-side policy), not copy-pasted into every prompt.
  • Few-shot examples earn their tokens: each one is there because the eval showed it helped, or it's removed.
  • A quarterly prompt review catches the next round of accumulation before it's 4,000 tokens again.
