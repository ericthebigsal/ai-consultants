AI capability prototype

Four new capabilities, built on the platform Chateau Salerno already has.

Everything here runs against one sample winery — Kestrel Ridge Vineyards, a 4,000-case Oregon producer with a 900-member wine club. The interface and the flows are what a build would produce. Every block of AI output is pre-generated for a fixed set of inputs and marked as such; nothing on these pages calls a model.

4 capabilities 1 sample winery ~900 club members static prototype

01 · Natural-language segments

Describe the audience, get the segment

A marketer types the audience in plain English and the platform resolves it against the existing segment engine — filter tree, member count, sample, all inspectable.

Replaces / adds

Replaces: building a segment by hand across five filter screens. Adds: nothing new in the data model — the model writes a normal, editable segment.

Open the segments prototype

02 · Campaign & journey drafting

A goal in, a journey out

From an outcome like “win back lapsed club members before the fall release,” the platform drafts the multi-step email and SMS journey — timing, branch logic, and first-draft copy in the winery’s voice — on the canvas the marketer already edits.

Replaces / adds

Replaces: a blank journey canvas and a copywriting session. Adds: a structured first draft the marketer edits and approves before anything sends.

Open the journeys prototype

03 · Churn & lifetime-value prediction

Which members are about to leave, and why

Every club member scored weekly on cancellation risk and predicted 24-month value, with the factors behind each score shown in the platform’s own events — visits, allocation choices, opens — and a one-click path into a win-back journey.

Replaces / adds

Replaces: noticing a member left after they cancelled. Adds: an at-risk segment that feeds the same tools as any other segment.

Open the retention prototype

04 · Tasting notes & product copy

The writing wineries put off

From the structured wine data already in the platform, draft the tasting note, the shop description, and the allocation email — consistently, in one voice, across every channel. The winemaker edits; they don’t start from a blank page.

Replaces / adds

Replaces: three separate writing tasks per release, done inconsistently or late. Adds: drafts generated from existing product fields, in the winery’s own voice.

Open the copy prototype

How to read these

The interface and the flows are representative of what a build would produce — the same segment object, the same journey canvas, the same product fields Chateau Salerno already has. The model output is pre-generated for the fixed Kestrel Ridge inputs shown on each page and is marked Pre-generated wherever it appears. Nothing here calls an API or stores anything.

The written case for the program — the business rationale and the statement of work — sits alongside this prototype in the engagement package.
