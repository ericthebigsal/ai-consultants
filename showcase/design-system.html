01 · Foundations

Color

Nine ramps, each with a named role. A token is only added when a screen needs a value the system can't already express — not the other way around.

One rule for red. color.signal means something is wrong or falling — a crossed threshold, a dropped metric, a failed job. It is never used for brand emphasis or decoration. This is the constraint the audit found most often broken.

04 · Governance

Keeping it current

A design system decays the day the team stops looking at it. This one is checked against the live app every week, and drift is surfaced as a diff, not a surprise.

Maintain Runs weekly against a crawl of the production app: flags any screen using a value outside the token set, groups the findings, and opens a review with a proposed fix. what counts as drift worth fixing versus a deliberate, documented exception.
  • Weekly drift check. Every production screen is compared to the token set. New off-token values become a grouped review item.
  • Change proposals. A new token or component variant starts as a written proposal with the screens that need it — same bar as a code change.
  • Ownership. One named person on the Northwind side approves every addition. The system is theirs, not ours.
What we hand over. The token files, the component specs, the weekly drift check wired into your CI, and a half-day session so your team can run all of it without us.
