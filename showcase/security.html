02 · Controls

The rules

Short enough that an engineer will actually read them before shipping.

  • Approved tools only. Customer or confidential data goes only to a provider on the approved list, with a signed DPA and, where the data class requires it, zero data retention.
  • Human review before action. A model output that changes a customer record, sends a message, or moves money is reviewed by a person before it takes effect. Read-only and draft outputs are exempt.
  • Logged and attributable. Every model call against customer data logs the input class, the model and version, and the requesting service. Retained 90 days.
  • New tool = a request. Adding an AI tool that touches non-public data is a written request with the data class and the purpose. One approver.

05 · Governance

Keeping it current

Maintain Re-runs the discovery scan weekly (SSO, expense feeds, egress logs), diffs it against the register, and opens a review item for any new tool or any approved tool whose config drifted. the risk call on anything new, and whether a drift is a violation or an approved exception.
Accelerate Assembles the evidence pack for the annual SOC 2 audit — control descriptions, sample logs, the DPA set, the register history — from the systems of record. what goes in front of the auditor.
  • Weekly re-scan. New tools and config drift become grouped review items, not surprises during an audit.
  • Quarterly control review. Each control is re-checked against a fresh sample of real activity.
  • One owner. A named person at Northwind approves every register change and every accepted risk.
What we hand over. The register wired to the discovery scan, the control set, the framework crosswalk, the audit-evidence job, and a working session so Northwind's security lead runs all of it.
